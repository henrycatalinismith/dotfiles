# Editing chezmoi-managed dotfiles

The files in `$HOME` are generated by chezmoi from the source repo at
`~/dotfiles`. If you edit the target file directly, the change won't be saved
in the repo and the next `chezmoi apply` will overwrite it.

## Workflow

1. **Check whether the target is managed:**
   ```sh
   chezmoi source-path ~/.config/foo/bar
   ```
   - If it prints a path, edit **that source file**.
   - If it errors with "not managed", the file isn't tracked. Edit it
     directly, then ask the user whether to start tracking it with
     `chezmoi add <target>`.

2. **Check for drift first:** run `chezmoi diff <target>`. If the target
   already has changes the source doesn't have, tell the user before you
   overwrite them. You may need to run `chezmoi re-add <target>` first, but
   only for files that aren't templates.

3. **Edit the source file.** Watch out for chezmoi naming conventions:
   - `dot_` → `.`, `private_` → mode 0600/0700, `executable_` → +x
   - `.tmpl` suffix → Go template. Keep `{{ }}` blocks intact and edit around
     them. Never replace template output with literal values.
   - `run_onchange_*` / `run_once_*` scripts run during apply.
   - New files: create them in the source using the correct prefixes.
     Alternatively, write the target and run `chezmoi add <target>`. Use
     `chezmoi add --template` if machine-specific values are needed.

4. **Apply and verify:**
   ```sh
   chezmoi apply <target>
   chezmoi diff <target>   # should be empty
   ```

5. **Report** the source path you edited. Don't commit unless the user asks.

## Notes
- `chezmoi managed` lists every managed path.
- `chezmoi cat <target>` shows the rendered result of a template.
- Never run a bare `chezmoi apply --force` across the whole tree. Other
  uncommitted work may exist.
